# store-001：施設特有の補正ルール（追記用）

## 適用範囲
- ACCIDENT_REPORT_SYSTEM_PROMPT の共通ルールはそのまま有効。ここに示すルールは施設固有の表現揺れ・重点箇所の補正案であり、共通ルール（5W2H記述、推測禁止、JSON schema遵守等）を上書きしてはならない。

## 共通的な運用指針（施設特有）
- 記述は「事実」優先：画像・現地確認・目撃情報・維持管理記録で確認できる事実を短く簡潔に記載する。推測は避け、どうしても記載する場合は必ず「確認中」「と思われる」等で明示する。
- 不確定情報は分離：現地観察（what/how/where）と原因推測（why）や調査予定は段落を分ける。
- 施設呼称に準拠：場所・設備の呼称は施設で運用している正式名称（フロア＋設備名）に合わせる。

## フィールド別ルール
- fiveWTwoH.where
  - フォーマット：建物名 + 階（必要なら階範囲） + 設備名／通路等（例：本館 1-2階 エスカレーター）。
  - 曖昧な表現（「南側廊下」等）は可能であれば具体化する。確認できない場合は「位置：確認中」と記載。

- fiveWTwoH.what
  - 観察で確認できる対象を短く1文で記載（例：「三角ボードが落下」）。複数の事象がある場合は箇条で列挙する。
  - 現地の写真で判別できない詳細（物質種別・数量等）は「確認中」とする。

- fiveWTwoH.how
  - 画像や現地で確認できる挙動・状態を記述（例：「アクリル板が脱落して床面に落下・散乱したと推測される」）。
  - 部材名は資産リストや写真で照合して特定できる場合に用いる。未確認の場合は「〜と思われる」や「確認中」を付す。

- fiveWTwoH.why
  - 原因は原則「不明／要調査」とし、確認済みの施設固有情報（例：常時雨漏り箇所、当日の大雨、直近の作業履歴、目撃者報告）を事実として追記する。
  - 例："原因は現時点で不明。常時雨漏りが発生している箇所であり、当日の大雨が一因と考えられる（要点検）。"
  - 個人の責任帰属（例：特定作業者の接触）が確認できる場合のみ明記し、未確認のときは名指ししない。

- treatment
  - 安全措置表記は施設運用用語に統一する（例：「カラーコーン設置」「立入禁止表示」など）。ただし、現地で実際に使われている器具・措置に合わせて記載すること。
  - 写真取扱い・写真台帳に関する注意書き等はそのまま残す。

## 記載例（運用ガイドとして）
- before: "本館 3階 南側廊下"
  - after: "本館 1-2階 エスカレーター"（現地確認での正式呼称に合わせる）
- before: 長文での推測混在
  - after: "三角ボードが落下"（観察事実を簡潔に）
- before: "バリケード設置"
  - after: "カラーコーン設置"（施設運用語に合わせる）

## 運用手順
- レポート作成時はまず画像・現地・保守履歴（漏水記録等）・当日の気象記録を確認し、事実として記載できる項目のみを一次記載する。
- 不確定項目は明確に「確認中」とマークし、追記があれば更新履歴を残す。

## 追記事項
- 本ルールは手作業修正傾向に基づく補助ルールであり、個別事案での例外（実際にバリケードしか無い等）は現況優先とする。
